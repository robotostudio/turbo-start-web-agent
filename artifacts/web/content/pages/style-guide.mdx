## Colour

The palette sits at the bottom of the design system file. That is the one place a raw colour value
belongs, because it is the definition rather than a use. Everywhere else, every
colour is a semantic token: `bg-card`, `text-muted-foreground`,
`ring-foreground/10`.

| Token | Means |
| --- | --- |
| `background` / `foreground` | The page and the ink on it |
| `card` / `card-foreground` | A raised surface and its ink |
| `primary` / `primary-foreground` | The brand fill: buttons, the header pill |
| `muted` / `muted-foreground` | Quiet fills and secondary copy |
| `accent` / `accent-foreground` | Hover and active states |
| `border` / `input` / `ring` | Hairlines, field edges, focus rings |

`bg-black/10` compiles, but it is wrong: `foreground` is the token that means
"the ink colour", and it moves when the palette does. Re-theming a client site
means editing the values of these tokens, never renaming or removing one.

## Type

One class per role. Each bundles size, weight, line-height and tracking, so a
heading is a single class rather than four that can drift apart between two
Blocks. Sizes given as a range are `clamp()`, so one class holds at every width
and no role needs an `sm:` twin.

| Role | Size | Use it for |
| --- | --- | --- |
| `type-display` | 40 to 72px | The one biggest statement on a page. Once only. |
| `type-title` | 36 to 52px | A page title that is not a Hero |
| `type-heading` | 28 to 36px | A section heading |
| `type-subheading` | 20px | A card, entry, or FAQ title |
| `type-lead` | 18px | The supporting line under a heading |
| `type-para` | 16px | Body and card copy |
| `type-caption` | 14px | Dates, bylines, roles, small labels |
| `type-overline` | 12px | Uppercase micro-labels |

Add only a colour alongside a role: `type-heading text-foreground`. Do not
re-specify `font-*`, `tracking-*`, `leading-*`, or `text-balance`. The role sets
them, and repeating one is how two Blocks start to disagree.

## Surfaces

`card` is the filled surface every Block draws on: ground colour and corner in
one class. Padding stays at the call site, because it genuinely differs by card
size.

```
card p-6 sm:p-8      a tile
card p-8 sm:p-12     a panel
card p-2             a media frame
```

Never write `rounded-3xl bg-card` by hand. An outlined card, like the raised
plan in Pricing, and an image frame, like Team, are different surfaces and keep
their own `border` or `outline`.

## Rhythm

Vertical gaps are named steps, never a margin guessed per Block. Five classes,
tightest first, each driven by one variable.

| Class | Gap | Between |
| --- | --- | --- |
| `stack-tight` | 8px | A card title and its own body |
| `stack-lede` | 16px | A heading and the lede under it |
| `stack-near` | 24px | Copy and its buttons, or a statement and the row it introduces |
| `stack-content` | 32 to 48px | A heading block and the grid or list under it |
| `section-y` | 64px | A section's own padding, top and bottom |

Every Block opens `page-inset section-y`. Writing `mt-8 sm:mt-12` instead is
the same class of bug as writing a raw type stack: it compiles, and it drifts.

## Changing the system globally

Each role and each step is one variable at the top of the stylesheet. Bumping
every paragraph by 2px is a single edit:

```
--type-para: 1.125rem;
```

Widening every section is `--rhythm-section`. Restyling every card corner
is `--radius-card`. Nothing in any Block needs touching, which is the whole
point: a global change should be one line, and an agent asked to make one
should never be editing fourteen components.

## Measure, radius, spacing

Prose runs to one of three widths: `max-w-note` (48ch), `max-w-lede` (60ch), or
`max-w-prose` (72ch). A line beyond roughly 90 characters is a defect, not a
preference.

`--radius` is the base, at 4px, and the ladder steps off it additively rather
than by multiplier. At a 4px base a multiplier scale collapses and every step
reads the same. Blocks name the surface, not the step: `rounded-media` (12px)
for an image frame, `rounded-card` (16px) for a card, `rounded-panel` (20px)
for a full-bleed panel, and `rounded-full` for every control.

Vertical gaps come from the rhythm steps above. Horizontal grid gaps are
`gap-4`, and gap values come from 2, 4, 6, 8 and 12, nothing else.
