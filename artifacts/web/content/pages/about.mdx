## The problem it solves

Most client sites end up with one of two failure modes. Either every copy change
comes back to a developer, and small edits queue for days, or the client gets a
CMS and the layout slowly drifts as they reach for tools nobody designed for the
job.

Harbour splits the difference. Content is data the client's agent may write.
Components, schemas and design tokens are code the client's agent may not touch.
The split is enforced at build time, not by convention.

## Content is MDX in git

Pages live under `content/`. Each page is data, not code: you assemble Blocks
and pass them literal values. There is no CMS and no database, so there is no
second copy of the content to keep in step, and no admin login to hand over.

```mdx
<Hero
  variant="centered"
  title="Your website, editable by any AI agent"
  primary={{ label: "Read the docs", href: "/about" }}
/>
```

That is the entire authoring surface. No imports, no wiring. Blocks are injected
into every content file automatically.

## The build is the gate

Bad frontmatter or bad Block props fail the build by design. If the build
passes, the content is valid.

That guarantee is worth being precise about. The lockdown walks the MDX tree and
every expression in it, rejecting anything that is not a literal value: no
imports, no function calls, no raw HTML elements, no event handler props, no
unsafe URLs. It is what makes "an agent may only edit content" true regardless
of what an agent attempts, rather than a rule an agent could choose to break.

What the build cannot check is whether the page reads well. Schemas enforce
shape, not meaning, so a section can pass every gate and still say the wrong
thing. Read the rendered page before calling a change done.
